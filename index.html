Overview
What is Wifite?
An orchestrator, not a standalone tool

Wifite is an automated Python script built for Linux penetration-testing distributions, such as Kali Linux. It acts as a "wrapper" around existing tools to simplify Wi-Fi auditing.

It automates the capture and testing of Wi-Fi passwords (WEP, WPA/WPA2, WPS-enabled networks) with minimal manual commands, for security professionals and ethical testers.

Wifite handles the wireless adapter, enables monitor mode, and automatically chains the right tools together, taking the manual guesswork out of the test.

Workflow
How It Works
01
Scanning
Scans for visible networks: signal strength, encryption type, connected clients.
02
Target Selection
The user picks a network from the list, or specifies it via BSSID / ESSID.
03
Automated Attacks
Launches attacks suited to the detected encryption (e.g. PMKID then handshake for WPA).
04
Cracking
Attempts to crack the password via a wordlist, or saves the capture for offline cracking.
Techniques
Attack Families
WPS
Offline Pixie-Dust, online brute-force PIN, and offline NULL PIN attack.
WPA / WPA2
Handshake capture via deauthentication, and clientless PMKID hash capture.
WPA3
SAE handshake capture; watch for transition-mode downgrade attacks.
WEP
Legacy techniques: fragmentation, chop-chop, and aireplay attacks.
Evil Twin
Rogue access point with a captive portal to capture credentials.
⚠ The exact number and behavior of attacks vary with the installed Wifite version.
Configuration
Control and Configuration
root@kali: ~# wifite --flags
--wep / --wpa / --wps-only
Restricts the audit to a single encryption type.
--pmkid
Specifically forces the PMKID attack (clientless).
--no-deauth
Stealth mode: skips the deauthentication phase.
--dict <file>
Supplies a custom wordlist for cracking.
--no-crack / --skip-crack
Prevents Wifite from auto-cracking the capture.
--dual-interface
Uses two adapters: one to capture, one for deauth / Evil Twin.
In Practice
Example Commands
Full automatic scan and attack
$ sudo wifite
Target a network by BSSID address
$ sudo wifite --bssid AA:BB:CC:DD:EE:FF
Targeted PMKID attack (clientless)
$ sudo wifite --pmkid
WPA networks only + custom wordlist
$ sudo wifite --wpa --dict rockyou.txt
⚠ These commands are not authorization to attack a third-party network: use them only on networks you own or are explicitly authorized to test.
Analysis
Risks and Limitations
⚡ Weak Passwords
Short or predictable keys fall quickly to a dictionary attack.
🔓 Outdated Protocols
Poorly configured WEP and WPA/TKIP remain vulnerable to legacy techniques.
👤 Rogue Access Points
An Evil Twin can fool users who aren't checking the network's identity closely.
⚙️ Misconfiguration
WPS left enabled by default or outdated firmware widen the attack surface.
ℹ Not every attack works on every network: success depends on the encryption in place, the hardware used, and the Wifite version.
Defense
Security Best Practices
🔒
Use WPA3
Or a properly configured WPA2-AES if WPA3 isn't available.
🚫
Disable WPS
Unless specifically needed: it's a frequent attack vector.
🔑
Strong Password
Long, unique, and unpredictable for the Wi-Fi network.
🔄
Update Hardware
Keep routers and access points current on firmware.
👁️
Watch for Unknown APs
Spot suspicious or duplicated access points on your network.
✅
Regular Audits
Test your own network on a planned, legal basis.
